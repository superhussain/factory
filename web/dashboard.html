      Automatic pickup Hosts

      Hosts come from Settings, Hosts. Only active hosts pick up work. A project value replaces the global one whole.

      Backlog triage

      When on, factory.py backlog add asks Cloudflare's clef-flash model whether a new item should be built without your review under these rules. Its yes probability, as a percent, is the confidence. At or above the threshold, the item moves to the idea column for pickup. Below it, the item waits here for you. Items that recommend deny always wait. Items that ask questions also wait, with the model's pick and a reason for each answer. Rules cannot contain links, secrets or instructions to skip review. A project value replaces the global one whole.

      Batch follow-ups

      Pickup holds follow-ups and ideas that backlog triage queued until a project has this many of them, or the oldest has waited this many hours without an update. Then one session builds them together. Ideas a person adds, approves or prioritizes never wait. A project value replaces the global one whole.

      Archive old jobs

      The Worker checks once an hour. Only merged and closed jobs move: never one with a claim, a question for you, an escalation, automerge, a queued or running build, unread deny notes or a pending Tracer mirror, unless Tracer is off. Archived jobs keep their files and open read-only from links. This setting applies to all projects.

      Tracer integration

      Off by default. On shows Follow in Tracer, Tracer links, task lists and Building in Tracer, and lets devices with tracer.json call Tracer. Turning it off keeps board fields and tracer.json as they are, so turning it back on resumes where it stopped. This setting applies to all projects.

          Scheduler
          
      
          Automatic pickup needs two things on each host: a scheduler that runs factory.py pickup every 5 minutes, and a launcher that starts one agent session per idea. Nothing here is saved. Copy a snippet, then replace each placeholder with this host's values.
          
      
          What runs pickup
          
      
            
        
          • Scheduler: the host's own timer, such as cron, launchd or Task Scheduler. It runs pickup every 5 minutes. Pickup never calls a model and prints nothing when there is no work.
            • 
        
          • Launcher: a command in <home>/launchers.json, one per route in routes.md. Pickup runs it in the project's checkout to start a session for the claimed idea. Any program that accepts the values below works.
            • 
      
          
      
          Placeholders
          
      
            
        
          • <installed-skill>: the folder where the factory skill is installed on this host.
            • 
        
          • <home>: this host's factory home, the folder that holds config.md and launchers.json.
            • 
        
          • <launcher bin dir>: the folder that holds your launcher program, so the scheduler finds it on PATH.
            • 
        
          • <program> and <arg>: your launcher program and its arguments.
            • 
      
          
      
          launchers.json
          
      
          Map each route name to a command. Pickup replaces {id}, {project}, {repo_path}, {session}, {provider}, {model}, {effort} and {prompt} in every argument, where {prompt} is /factory idea <id> --session <tag>, a blank line, and the standing instruction for unattended runs. A deny-notes launch sends /factory deny-notes <id> --session <tag> in place of the idea command. Unknown braces stay literal. The launcher also gets each value as a FACTORY_ environment variable, such as FACTORY_JOB_ID.
          
      
          Standing instruction for unattended runs
          A standing instruction from the user, the person you are working for. It is about how your turns end. This factory session runs unattended: a message with no tool call in it ends your turn, nothing wakes you afterwards, and the job stalls until a sweep finds it. The user has seen you end turns in four ways while factory work was still owed, and does not want any of them. One: a summary that closes by announcing the next step, such as reviewers running and verdicts to be recorded as they land, with no tool call, so the next thing never starts. Two: an offer to carry on unless the user would prefer otherwise. Three: a list of decisions for the user when, by your own account, none of them blocks the rest of the work. Four: deciding that this is a good place to report, because the turn has been long or a stage is done. Status notes and recommendations are welcome, but put them in the same message as your next tool call. While an agent or background command you started is still running, wait for it and handle its result instead of ending the turn. Stop only at a real stop: the job is at needs-human, merged or closed, its PR waits at pr-open for a person, a step in these instructions says stop, or nothing can move without the user. This does not override the security floors, the confirmation a risky or destructive action needs, or any rule that holds work for a human.

          Try it first
          
      
          This prints what pickup would launch and changes nothing.
          
      
          python3 <installed-skill>/runtime/factory.py pickup --dry-run
          
      
          Run it every 5 minutes
          
      
          
        
        
        
      
          
      
          
        
          Linux and WSL. Add this line with crontab -e.
          
        
          */5 * * * * PATH=<launcher bin dir>:/usr/bin:/bin python3 <installed-skill>/runtime/factory.py pickup >> <home>/logs/pickup.log 2>&1
          
        
          WSL without systemd needs service cron start, plus the /etc/wsl.conf [boot] line.
          
      
          
      
          
        
          macOS. Save this as ~/Library/LaunchAgents/factory.pickup.plist.
          
        
          <?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>factory.pickup</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/bin/python3</string>
    <string><installed-skill>/runtime/factory.py</string>
    <string>pickup</string>
  </array>
  <key>EnvironmentVariables</key>
  <dict><key>PATH</key><string><launcher bin dir>:/usr/bin:/bin</string></dict>
  <key>StartInterval</key><integer>300</integer>
  <key>StandardOutPath</key><string><home>/logs/pickup.log</string>
  <key>StandardErrorPath</key><string><home>/logs/pickup.log</string>
</dict>
</plist>
          
        
          Then load it.
          
        
          launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/factory.pickup.plist
          
      
          
      
          
        
          Windows. Save this wrapper as %USERPROFILE%\.config\factory-pickup.cmd.
          
        
          @echo off
set "PATH=<launcher bin dir>;%PATH%"
py -3 <installed-skill>\runtime\factory.py pickup >> <home>\logs\pickup.log 2>&1
          
        
          Then create the task.
          
        
          schtasks /Create /TN factory-pickup /SC MINUTE /MO 5 /TR "%USERPROFILE%\.config\factory-pickup.cmd" /F
          
        
          Python on Windows has no time zone data. Install it so usage-limit reset times parse. Without it, limits default to 60 minutes.
          
        
          py -3 -m pip install --user tzdata
